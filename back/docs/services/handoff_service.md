# Implementation Plan: Handoff Service (`handoff_service.py`)

## Brief description of the requirements and goals of the feature
This service manages the critical transition of a conversation from the automated bot to a human agent. It is responsible for triggering the handoff, assigning the conversation to an available agent, marking it as complete after resolution, and calculating performance metrics for the interaction. Its main goal is to ensure a seamless and efficient escalation process.

## Architecture and design
The `HandoffService` coordinates the state changes between `Conversation` and `Lead` models and their respective repositories.

- **`trigger_handoff`**: This is the entry point for escalation. It's called by the `ConversationOrchestrator` when certain conditions are met (e.g., high lead score, user request). It changes the conversation status to `PENDING_HANDOFF` and generates a natural transition message to inform the user.

- **`assign_to_human`**: Once a human agent accepts the handoff request (a step likely handled by the UI/API layer), this function is called to formally assign the conversation to that agent. It changes the status to `ACTIVE_HUMAN`.

- **`mark_as_completed`**: After the human agent has resolved the user's query (e.g., scheduled an appointment), this function is called. It sets the conversation status to `COMPLETED`, updates the associated lead's status to `SCHEDULED`, and calculates key performance metrics for the handoff process.

- **`return_to_bot`**: Provides a mechanism for a human agent to return a conversation to the bot if the escalation was unnecessary or the user's query can be handled by automation again.

- **Metrics Calculation**: The `_calculate_metrics` method computes important KPIs, such as total conversation time, time to handoff, and human interaction time. This data is crucial for the analytics dashboard to measure the efficiency of the bot and the human agents.
